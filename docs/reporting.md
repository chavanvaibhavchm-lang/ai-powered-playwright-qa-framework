# Reports and real execution history

Verified installed CLI: **Allure 3.20.1**. `allure-playwright` 3.13.0 emits raw
results; `allure-js-commons` supplies labels/steps. The Allure 3 CLI uses Node,
not the Allure 2 Java CLI. `allure generate --help` was inspected before scripts
were implemented; do not copy Allure 2 `--clean` syntax into these scripts.

```powershell
npm run allure:clean
npm test
npm run allure:generate
npm run allure:open
```

`allure:clean` deletes only the resolved project `allure-results` folder, with a
path containment guard. It preserves history, source and baselines. Generate
once after each genuine test launch, not repeatedly to invent runs.
Generation rebuilds only the guarded generated `allure-report` folder so stale
landing pages cannot survive a CLI configuration change. The actual Allure 3
single configured Awesome plugin writes the current `allure-report/index.html`;
`allure:open` targets that generated report directory. History is kept separately
and is preserved. A raw-results fingerprint prevents adding duplicate history
entries when regenerating the same execution collection after a report edit.

Reports: terminal list, native HTML (`npx playwright show-report`), machine-readable
`test-results/summary.json`, Allure HTML. Allure labels include epic, feature,
requirement story, stable testcase ID, owner, severity and description. UI tests
use named business steps plus captured Playwright calls. The automatic fixture
does not request a browser for offline API/AI tests.
Native HTML/JSON represent the latest invocation, while Allure accumulates the
current collection. Use `npm run record:run -- label` immediately after a suite to
save sanitized evidence and archive that invocation's HTML in `.local/reports/label`.

Failure artifacts: PNG screenshot, WebM video, Playwright trace ZIP; adapter copies
attachments into Allure raw results. Persona defect reproductions explicitly
attach evidence on successful reproduction. Accessibility attaches full axe JSON;
PDF download tests attach the genuine artifact. No secret environment variables,
private passwords or local paths are put into report environment metadata.

`environment.properties` is generated by the reporter. `executor.json` records
local execution or public GitHub workflow/run URLs. Allure 3 also derives CI
information from the supported CI environment; the local executor file is raw
portable metadata and is not a claim that an Allure 2 executor panel is present.
The actual inspected Allure 3 dashboard displayed the local executor alongside
the five environment fields; this is captured in `evidence/report-verification.json`.

Allure 3 history uses a real JSONL file at `test-history/allure-history.jsonl`
with a maximum of 20 entries. Never copy Allure 2 history directories. History
contains only generated reports from actual runs; early bootstrap reports may
combine several diagnostic invocations. Compare like-for-like suite scopes when
interpreting charts. Local history is ignored in Git and retained across cleanup.
GitHub uploads history but does not restore it across workflow runs, so persistent
CI trends are not claimed. No Pages publishing is configured.
